# 通用前缀模板

> 每次任务前，把本模板 + 对应任务提示词拼接成完整提示词。
> 用 `---` 分隔各部分。

---

## 完整模板

```text
【项目宪法】
{{在这里粘贴 docs/CONTEXT.md 的完整内容}}

【已实现接口】
{{在这里粘贴 docs/API.md 的完整内容}}

【当前进度】
{{在这里粘贴 docs/PROGRESS.md 的当前阶段}}

【任务】
{{在这里粘贴具体任务的提示词，比如 01-models.md 的内容}}

【开始前】
开始写代码前，请先用 5 句话复述：
1. 这个项目的架构原则
2. 本次任务要生成什么
3. 会依赖哪些已有类
4. 需要注意的约束
5. 输出格式

确认理解无误后再开始写代码。

【输出格式】
- 每个文件单独代码块
- 代码块前标注文件路径（如 // lib/models/course.dart）
- 完整输出，不省略
- 全部文件写完后，额外输出一份 API 接口清单，供我更新 docs/API.md
```

---

## 使用示例

以"生成数据模型"为例，拼好的提示词：

```text
【项目宪法】
（CONTEXT.md 全文）

【已实现接口】
（空）

【当前进度】
Phase 1.1 数据模型：全部待完成

【任务】
生成 Course、TimePlace、UserOverride 三个数据模型...

【开始前】
开始写代码前，请先用 5 句话复述...

【输出格式】
...
```

---

## 省 Token 技巧

1. **API.md 只带相关部分**：生成课表 UI 时不需要携带 PluginMeta 的接口
2. **Phase 切换时开新对话**：避免上下文超长
3. **用"继续"接续截断输出**：不要重新发提示词
4. **让 AI 复述理解后再写**：避免生成一大堆错代码
5. **把长文件拆成多个提示词**：比如数据模型一次只生成 3 个

---

## 各模式选择

| 任务类型 | 推荐模式 | 原因 |
|----------|----------|------|
| 模板化代码（数据模型、页面空态） | 普通对话 | 无需推理，快 |
| 复杂逻辑（主题合并、Provider 联动） | 深度思考 | 需要推理 |
| 调试报错 | 深度思考 | 需要根因分析 |
| 重构优化 | 深度思考 | 需要全局视角 |
| 长文件生成 | 深度思考 + 分段 | 避免截断 |
